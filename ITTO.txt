# **《PMBOK® 指南》第8版 40个流程真实 ITTO 穿透全景对照表**

## **💡 关于“XX更新”与“隐性术语拆解”的重构原则**

1. **去包袱化（Unpacking）**：将“项目文件更新”、“项目管理计划组件”、“其他规划过程的输出”等高层级术语全部拆解为底层真正的**具体工件**。  
2. **对等原则（Equivalence）**：所有标注为“XX更新（Updates）”的输出，在逻辑链条上等同于其“原件”，直接标明其流向的下一个目标。  
3. **隐性源头穿透（Hidden Origins）**：针对类似“活动清单（Activity List）”这种字面无法直接匹配的条目，在产出或消费端附带 【隐性穿透说明】，确保控制回路完全闭合。

## **一、 治理绩效领域 (Governance Performance Domain) —— 9个过程**

### **\#1 启动项目或阶段 (Initiate Project or Phase)**

* **真实输入 (Inputs)**：商业论证 (Business Case)、效益管理计划 (Benefits Management Plan)、协议 (Agreements)、事业环境因素 (EEFs)、组织过程资产 (OPAs).  
* **真实工具与技术 (T\&T)**：专家判断、数据收集（头脑风暴、焦点小组、访谈）、人际关系与团队技能（冲突管理、引导、会议管理）、项目画布 (Project Canvas)、职责分配矩阵.  
* **真实输出 (Outputs)**：  
  * **项目章程 (Project Charter)** → 流入 \#2, \#3, \#9, \#10, \#11, \#12, \#16, \#17, \#19, \#23, \#24, \#25, \#30, \#35  
  * **假设日志 (Assumption Log)** → 流入 \#7, \#9, \#11, \#12, \#17, \#24, \#30, \#31, \#36, \#37

### **\#2 整合与对齐项目计划 (Integrate and Align Project Plans)**

* **真实输入 (Inputs)**：  
  * 项目章程  
  * **【穿透：其他规划过程的输出】**（包含：各子管理计划 \#10, \#16, \#19, \#24, \#25, \#30, \#35 ；三大基准 \#13, \#17, \#21 ；以及需求文件、预测和应对措施）  
* **真实工具与技术 (T\&T)**：专家判断、数据收集（头脑风暴、核对表、焦点小组、访谈）、人际关系与团队技能（引导、会议管理）、会议、项目画布.  
* **真实输出 (Outputs)**：  
  * **项目管理计划 (Project Management Plan)** → 流入 \#3, \#4, \#5, \#6, \#7, \#9, \#10, \#13, \#16, \#19, \#35, \#36（注：后续所有子流程中所消费的“组件输入”物理源头全部在此）

### **\#3 规划采购策略 (Plan Sourcing Strategy)**

* **真实输入 (Inputs)**：项目章程、项目管理计划组件（范围、质量、进度、财务、资源管理计划及范围基准）、项目文件（里程碑清单、需求文件、需求跟踪矩阵、质量指标、资源需求、派工单、风险登记册、相关方登记册）、EEFs、OPAs.  
* **真实工具与技术 (T\&T)**：专家判断、市场调研、自制或外购分析、源头选择分析、文件分析.  
* **真实输出 (Outputs)**：  
  * **采购策略计划（含自制或外购决策、供方选择标准）** → 流入 \#8, \#9, \#20, \#32, \#34

### **\#4 管理项目执行 (Manage Project Execution)**

* **真实输入 (Inputs)**：项目管理计划、批准的变更请求 (来自 \#8)、工作绩效报告、经验教训登记册、里程碑清单、项目进度计划、需求跟踪矩阵、风险登记册/报告、EEFs、OPAs.  
* **真实工具与技术 (T\&T)**：专家判断、项目管理信息系统 (PMIS)、会议（如每日协调会）.  
* **真实输出 (Outputs)**：  
  * **可交付成果 (Deliverables)** → 流入 \#6, \#14  
  * **工作绩效数据 (Work Performance Data)** → 流入 \#14, \#18, \#22, \#28, \#29, \#34, \#40  
  * **问题日志 (Issue Log)** → 流入 \#7, \#8, \#9, \#23, \#24, \#26, \#33, \#34, \#36, \#37, \#39, \#40  
  * **变更请求 (Change Requests)** → 流入 \#8 评估与实施变更  
  * **【隐性穿透输出・项目文件更新（活动清单 Activity List）】**：随着 WBS 的具体工作包在执行中被团队物理拆解，该工件在此处首次产出并初始化 → 作为最新原件流向 \#17 进行进度模型精细化定义，以及流向 \#31 进行底层资源资源估算。

### **\#5 管理质量保证 (Manage Quality Assurance)**

* **真实输入 (Inputs)**：项目管理计划（所有组件）、项目文件（质量指标、质量控制测量结果）、组织过程资产（质量政策与程序）.  
* **真实工具与技术 (T\&T)**：质量审计 (Audits)、核对表、数据表现（鱼骨图、流程图）、决策制定、问题解决、过程改进.  
* **真实输出 (Outputs)**：  
  * **质量报告 (Quality Reports)** → 流入 \#7, \#9, \#15, \#27  
  * **变更请求 (Change Requests)** → 流入 \#8  
  * **项目管理计划/文件更新** → 视变动内容同等回流对应原件管线

### **\#6 管理项目知识 (Manage Project Knowledge)**

* **真实输入 (Inputs)**：项目管理计划、可交付成果 (来自 \#4)、项目团队派工单、资源分解结构 (RBS)、相关方登记册、EEFs、OPAs.  
* **真实工具与技术 (T\&T)**：专家判断、知识管理（事后回顾 AAR、故事讲述、回顾会议）、信息管理、人际关系与团队技能（积极倾听、政治意识）.  
* **真实输出 (Outputs)**：  
  * **经验教训登记册 (Lessons Learned Register)** → 流入 \#4, \#7, \#9, \#11, \#17, \#18, \#20, \#22, \#26, \#27, \#28, \#29, \#33, \#34, \#36, \#38, \#39, \#40（注：属于动态活页日志，追加最新组织智慧，全局消费）

### **\#7 监控项目绩效 (Monitor and Control Project Performance)**

* **真实输入 (Inputs)**：项目管理计划、工作绩效信息 (WPI) (来自 \#14, \#18, \#22, \#28, \#29, \#34, \#40 监控流的转化)、各类预测（成本预测、进度预测）、问题日志、假设日志、估算依据、质量报告、风险报告、协议.  
* **真实工具与技术 (T\&T)**：专家判断、数据分析（挣值分析 EVM、变动分析、趋势分析、根本原因分析）、项目仪表盘、信息辐射体、会议.  
* **真实输出 (Outputs)**：  
  * **工作绩效报告 (Work Performance Reports)** → 流入 \#8, \#27, \#33, \#40  
  * **变更请求 (Change Requests)** → 流入 \#8  
  * **项目文件更新（成本/进度预测、问题日志更新）** → 属于原件状态修正，流入 \#7 本身的下一次迭代循环与 \#8 变更评审作参考底稿

### **\#8 评估与实施变更 (Assess and Implement Changes)**

* **真实输入 (Inputs)**：变更请求 (来自全书 11 个过程的汇总抛出)、项目管理计划（变更/配置管理计划、三大基准）、估算依据、变更日志、需求跟踪矩阵、风险报告、工作绩效报告、EEFs、OPAs.  
* **真实工具与技术 (T\&T)**：专家判断、变更控制工具、数据分析（备选方案分析、成本效益分析）、决策制定（多标准决策分析、投票）、整体变更控制、待办列表管理（敏捷适用）.  
* **真实输出 (Outputs)**：  
  * **批准的变更请求 (Approved Change Requests)** → 流入 \#4 执行，以及 \#14, \#15, \#18 用于基准核准对齐  
  * **变更日志更新 (Change Log Updates)** → 流入 \#4, \#9, \#23, \#24, \#26, \#27（注：将变更状态固化，原件同等流向相关方管理与收尾流程）

### **\#9 收尾项目或阶段 (Close Project or Phase)**

* **真实输入 (Inputs)**：项目章程、项目管理计划（所有组件）、验收的可交付成果 (来自 \#15)、最终报告、商业文件、协议、采购文档、变更日志、问题日志、经验教训登记册、质量控制测量结果、风险报告.  
* **真实工具与技术 (T\&T)**：专家判断、数据分析（文件分析、回归分析、趋势分析）、会议.  
* **真实输出 (Outputs)**：  
  * **最终产品/服务或成果的移交 (Final Product/Service Transition)** → 物理交付给客户运营端  
  * **最终报告 (Final Report)** → 移交项目出资人及组织高层  
  * **组织过程资产更新（经验教训、收尾资产归档）** → 固化进组织历史数据库

## **二、 范围绩效领域 (Scope Performance Domain) —— 6个过程**

### **\#10 规划范围管理 (Plan Scope Management)**

* **真实输入 (Inputs)**：项目章程、项目管理计划、需求文件、风险登记册、相关方登记册、EEFs、OPAs.  
* **真实工具与技术 (T\&T)**：专家判断、数据收集（访谈、问卷调查）、数据分析、测试和检查规划.  
* **真实输出 (Outputs)**：  
  * **范围管理计划 (Scope Management Plan)** → 流入 \#2, \#3, \#11, \#12, \#13, \#14, \#16, \#17, \#31  
  * **需求管理计划 (Requirements Management Plan)** → 流入 \#2, \#11, \#23

### **\#11 启发与分析需求 (Elicit and Analyze Requirements)**

* **真实输入 (Inputs)**：项目章程、范围与需求管理计划、商业论证、协议、假设日志、经验教训登记册、相关方登记册.  
* **真实工具与技术 (T\&T)**：专家判断、数据收集（标杆对照、头脑风荒、访谈、问卷）、人际技能（名义小组技术 NGT）、设计思维、优先级排序/分级、会议.  
* **真实输出 (Outputs)**：  
  * **需求文件 (Requirements Documentation)** → 流入 \#2, \#3, \#9, \#10, \#12, \#13, \#14, \#15, \#23, \#25, \#30, \#36  
  * **需求跟踪矩阵 (Requirements Traceability Matrix)** → 流入 \#3, \#4, \#8

### **\#12 定义范围 (Define Scope)**

* **真实输入 (Inputs)**：项目章程、范围管理计划、需求文件、假设日志、EEFs、OPAs.  
* **真实工具与技术 (T\&T)**：专家判断、产品分析 (Product Analysis)、数据分析、分解技术、引导.  
* **真实输出 (Outputs)**：  
  * **项目范围说明书 (Project Scope Statement)** → 流入 \#2, \#13, \#17  
  * **项目文件更新（需求文件修正更新）** → 作为最新需求底稿回流到范围后续过程

### **\#13 制定范围结构 (Develop Scope Structure)**

* **真实输入 (Inputs)**：项目管理计划、项目范围说明书、需求文件、批准的变更 (来自 \#8).  
* **真实工具与技术 (T\&T)**：专家判断、头脑风暴、分解技术 (Decomposition).  
* **真实输出 (Outputs)**：  
  * **范围基准 (Scope Baseline，含 WBS 及 WBS词典)** → 流入 \#2, \#3, \#8, \#15, \#18, \#20, \#21, \#30, \#31, \#38  
  * **用户故事 (User Stories)、产品待办列表 (Product Backlog)** → 流入 \#2, \#18（注：敏捷/混合生命周期下的范围等同物）

### **\#14 监督与控制范围 (Monitor and Control Scope)**

* **真实输入 (Inputs)**：范围/质量管理计划、需求文件、绩效测量基准、质量指标、工作绩效数据 (来自 \#4)、批准的变更请求、可交付成果.  
* **真实工具与技术 (T\&T)**：数据分析（偏差分析、趋势分析、根本原因分析）、绩效审查、审计与检查、测试/产品评估、流程自动化.  
* **真实输出 (Outputs)**：  
  * **工作绩效信息 (WPI \- 范围状态)** → 流入 \#7 绩效聚合  
  * **确认的可交付成果 (Verified Deliverables)** → 物理通过内部质检，流入 \#15 等待客户或发起人验收  
  * **质量控制测量结果 (Quality Control Measurements)** → 流入 \#9, \#15  
  * **质量报告 (Quality Reports)** → 流入 \#7, \#15  
  * **变更请求 (Change Requests)** → 流入 \#8

### **\#15 确认范围 (Validate Scope)**

* **真实输入 (Inputs)**：范围基准、需求文件、确认的可交付成果 (来自 \#14)、质量控制测量结果、质量报告、工作绩效数据.  
* **真实工具与技术 (T\&T)**：检查 (Inspection)、数据分析、决策制定、客户会谈与测试、审查会议.  
* **真实输出 (Outputs)**：  
  * **验收的可交付成果 (Accepted Deliverables)** → 获得客户签字批准的文件，流入 \#9 做最终收尾行政移交  
  * **变更请求 (Change Requests)** → 流入 \#8（注：若验收未通过，抛出变更以期进入返工控制回路）  
  * **工作绩效信息（验收状态报告）** → 流入 \#7

## **三、 进度绩效领域 (Schedule Performance Domain) —— 3个过程**

### **\#16 规划进度管理 (Plan Schedule Management)**

* **真实输入 (Inputs)**：项目章程、项目管理计划（范围管理计划）、开发方法、EEFs、OPAs.  
* **真实工具与技术 (T\&T)**：专家判断、数据分析（备选方案分析）、会议.  
* **真实输出 (Outputs)**：  
  * **进度管理计划 (Schedule Management Plan)** → 流入 \#2, \#3, \#17, \#18, \#19, \#31

### **\#17 开发进度模型 (Develop Schedule)**

* **真实输入 (Inputs)**：  
  * 项目章程、进度管理计划、项目范围说明书、开发方法、协议、EEFs、OPAs.  
  * **【隐性源头对齐・输入组件】**：活动清单 (Activity List)与活动属性 (源自 \#4 的项目文件更新初始化，并在本流程 Step 1 中转化)、工期估算与估算依据 (来自本流程内部 Step 3 的循环输入)、逻辑关系、提前量与滞后量、依赖关系、项目进度网络图、资源需求 (来自 \#31)、资源日历、风险登记册.  
* **真实工具与技术 (T\&T)**：  
  * *内部步骤核心技术*：1. 定义活动（分解技术、滚动波浪规划） | 2\. 确定顺序（紧前关系绘图法 PDM、提前/滞后量） | 3\. 估算努力与工期（**估算技术：参数、类比、三点、自下而上、敏捷估算**、储备分析） | 4\. 调校进度（关键路径法 CPM、进度压缩：赶工/快跟、资源优化：资源平衡/平滑）.  
  * *系统工具*：项目管理信息系统 (PMIS)、敏捷发布规划、投票.  
* **真实输出 (Outputs)**：  
  * **进度基准 (Schedule Baseline)** → 流入 \#2, \#8, \#18  
  * **项目进度计划 (Project Schedule)** → 流入 \#3, \#4, \#18, \#20, \#21, \#24, \#25, \#26, \#30, \#31, \#32, \#33, \#34, \#38  
  * **项目日历 (Project Calendar)** → 流入 \#3, \#18  
  * **项目文件更新（确立/修正后的活动清单、活动属性、里程碑清单、进度网络图）** → 此时活动清单等工件被精细化确立，作为最新、高精度原件流向 \#31 估算资源和 \#4 进行物理日常执行.

### **\#18 监督与控制进度 (Monitor and Control Schedule)**

* **真实输入 (Inputs)**：进度管理计划、进度基准、绩效测量基准、项目进度计划、工作绩效数据 (来自 \#4)、产品待办列表、项目日历、资源日历、风险登记册.  
* **真实工具与技术 (T\&T)**：数据分析（挣值分析、燃尽图/燃起图、趋势/偏差分析、假设情景分析）、关键路径法、进度压缩、资源优化、团队速度 (Velocity)、每日协调会、迭代评审会、待办列表精炼.  
* **真实输出 (Outputs)**：  
  * **工作绩效信息 (WPI \- 进度偏差)** → 流入 \#7  
  * **进度预测 (Schedule Forecasts)** → 流入 \#7  
  * **变更请求 (Change Requests)** → 流入 \#8  
  * **项目管理计划/文件更新** → 视最新基准/计划更新同步流入 \#7 监控循环与 \#4 执行端

## **四、 财务绩效领域 (Finance Performance Domain) —— 4个过程**

### **\#19 规划财务管理 (Plan Financial Management)**

* **真实输入 (Inputs)**：项目章程、项目管理计划（进度管理计划、风险管理计划）、EEFs、OPAs.  
* **真实工具与技术 (T\&T)**：专家判断、数据分析（备选方案分析）、会议.  
* **真实输出 (Outputs)**：  
  * **财务管理计划 (Financial Management Plan)** → 流入 \#2, \#3, \#21, \#22  
  * **资金筹措策略 (Funding Strategy)** → 流入 \#2, \#21

### **\#20 估算成本 (Estimate Costs)**

* **真实输入 (Inputs)**：质量管理计划、范围基准、项目进度计划、**【穿透输入：活动清单】**、资源需求、自制或外购决策 (来自 \#3)、经验教训登记册、风险登记册、EEFs、OPAs.  
* **真实工具与技术 (T\&T)**：专家判断、**估算技术（类比估算、参数估算、自下而上估算、三点估算）**、数据分析（储备分析、质量成本 COQ）、PMIS、决策制定.  
* **真实输出 (Outputs)**：  
  * **成本估算 (Cost Estimates)** → 流入 \#21, \#31  
  * **估算依据 (Basis of Estimates)** → 流入 \#7, \#8, \#9, \#17, \#18, \#21, \#22  
  * **项目文件更新** → 更新假设、风险等原件数据并回流管线

### **\#21 制定预算 (Develop Budget)**

* **真实输入 (Inputs)**：财务管理计划、范围基准、项目进度计划、成本估算、估算依据、风险登记册、商业论证、效益管理计划、协议、EEFs、OPAs.  
* **真实工具与技术 (T\&T)**：专家判断、成本汇总 (Cost Aggregation)、数据分析（储备分析）、历史信息审查、资金限制平衡 (Funding Limit Reconciliation)、融资 (Financing).  
* **真实输出 (Outputs)**：  
  * **成本基准 (Cost Baseline)** → 流入 \#2, \#8, \#18, \#22, \#32, \#37, \#38  
  * **项目资金需求 (Project Funding Requirements)** → 流入 \#22  
  * **项目文件更新（成本估算/进度模型微调）** → 作为修正后的原件回流对应的估算流

### **\#22 监督与控制财务 (Monitor and Control Finances)**

* **真实输入 (Inputs)**：财务管理计划、成本基准、绩效测量基准、项目资金需求、工作绩效数据 (来自 \#4)、经验教训登记册.  
* **真实工具与技术 (T\&T)**：专家判断、数据分析（挣值分析 EVM、趋势分析、储备分析）、完工尚需绩效指数 (TCPI)、PMIS.  
* **真实输出 (Outputs)**：  
  * **工作绩效信息 (WPI \- 成本偏差)** → 流入 \#7

* **真实输入 (Inputs)**：风险管理计划、三大基准（范围、进度、成本基准）、风险登记册、风险报告、假设日志、成本/工期估算、资源需求、相关方登记册、EEFs、OPAs.  
* **真实工具与技术 (T\&T)**：专家判断、数据收集与分析（访谈）、风险分类 (Risk Categorization)、数据表现（概率和影响矩阵）、数据分析（风险概率与影响评估、蒙特卡洛模拟 Monte Carlo Simulation、敏感性分析、决策树分析、影响图）、人际与团队技能（引导）.

* **真实输入 (Inputs)**：资源/风险/财务/质量管理计划、三大基准、风险登记册、风险报告 (由 \#37 迭代校准更新后的最新版本)、经验教训登记册、项目进度计划、团队派工单、资源日历、相关方登记册、EEFs、OPAs.

  * **应对措施 (Response Actions)** → 固化进日常工作流
